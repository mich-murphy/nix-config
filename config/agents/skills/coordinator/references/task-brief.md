# Task brief

Keep one compact record in the repository's existing task/handoff location.
Replace placeholders; omit unused sections. The parent maintains this record.

## Checkout and continuation

- Repository/worktree path, branch, HEAD / task base:
- Pre-existing dirty paths/diffs (staged, unstaged, untracked); task changes:
- Relevant PR/head / live review and check state, or access limits:

## Scope and acceptance

- Objective / actual deliverables:
- Acceptance criteria:
- Exclusions / authority limits:
- Runtime capabilities / missing live progress or steering visibility:

## Ownership and work

- Parent (requirements acceptance and brief):
- Workers: ID, objective, owned paths; verified active / completed-stopped / unknown,
  with current status/contact evidence; release or explicit reassignment if any.
- Read-only reviewers, shared-file coordination, dependencies (if any):

## Material decisions and corrections

- Authoritative decisions (including exclusions), accepted/completed slices:
- Decision or observed gap → owner / required change / expected evidence.
- Correction status: sent / acknowledged / uptake observed / verified (or unverified).
  Include evidence pointers and unresolved disagreements; do not equate delivery
  with acknowledgement or acknowledgement with uptake.

## Verification and acceptance

- Worker quality: exact commands, outcomes, evidence pointers, limitations.
- Evidence source: commit + relevant dirty diff/file identity; current / stale / unknown.
- Parent requirements review: criterion → observed evidence / gap / acceptance status.
- Correction recheck: corrected diff / rerun commands and outcomes / stale evidence.
- Final acceptance: pending / accepted / incomplete / blocked, with reason.

## Next action

- Next owner and action; unresolved ownership/capability blocker or decision if needed.
  On resume, reconcile this record with live tools/checkout before dispatch or takeover.
