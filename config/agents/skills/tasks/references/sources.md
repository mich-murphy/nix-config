# Evidence and Provenance

This skill is a local-trial synthesis. Its strongest boundaries come from the
installed workflow contracts; its task-sizing heuristics come from lower-
certainty practitioner evidence.

- The local [Neo delivery contract](../../neo/references/delivery.md) requires
  thin vertical behaviors, focused verifiers, real evidence, compatibility,
  rollback, and replan conditions. The local
  [Ship readiness contract](../../ship/references/readiness-and-stops.md)
  defines what one implementation agent may safely admit. These are direct
  package contracts, not evidence that decomposition improves outcomes.
- [Agentic Workflow Principles](https://github.com/mich-murphy/agentic-workflow-research/blob/main/docs/foundations-and-synthesis/agentic-workflow-principles-summary.md#structure-work-vertically)
  and [Design Before Code](https://github.com/mich-murphy/agentic-workflow-research/blob/main/docs/foundations-and-synthesis/design-before-code-for-agentic-engineering.md#4-delivery-design-turn-decisions-into-verifiable-slices)
  synthesize vertical, verifiable delivery. Their recommendation is based on
  low-certainty practitioner consensus and should be trialled locally.
- [Dillon Mulroy's workflow](https://github.com/mich-murphy/agentic-workflow-research/blob/main/docs/practitioner-workflows/dillon-mulroy-workflow.md#3-convert-the-design-into-a-ticket-graph)
  is a low-certainty implementation report for dependency-linked vertical
  tickets that fit one fresh context.
- [Dex Horthy's workflow](https://github.com/mich-murphy/agentic-workflow-research/blob/main/docs/practitioner-workflows/dex-horthy-current-workflow.md#context-management)
  reports a fixed warning near 100,000 tokens and fresh-context compaction.
  This is very-low-certainty experience evidence, not a general model benchmark
  or a guarantee for 200k-class contexts.
- [Model and Effort Selection](https://github.com/mich-murphy/agentic-workflow-research/blob/main/docs/tools-models-and-orchestration/official-anthropic-openai-model-guidance.md#context-and-cost-efficiency)
  provides moderate controlled-evaluation support for minimizing irrelevant
  context and measuring cost per accepted task, not for a universal task size.

Evaluate the skill against accepted Ship outcomes, plan-coverage misses,
replans caused by bad boundaries, context-warning crossings, review rework,
latency, and tokens per accepted task. Do not use task count, estimated tokens,
or routing activation alone as quality.
