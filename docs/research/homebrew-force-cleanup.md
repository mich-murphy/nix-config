# Homebrew forced-cleanup investigation

## Verdict

The remembered rationale is close, but the deprecated feature was
`brew bundle install --cleanup`, not `zap`.

The repository history does not record why `--force-cleanup` was added, so its
original intent cannot be proven. Its timing and effect are consistent with a
compatibility fix for Homebrew's new noninteractive-cleanup requirement. The
flag is redundant with the currently locked nix-darwin version.

## Chronology

- `cleanup = "zap"` entered this repository on 27 March 2024, without an
  explicit `--force-cleanup` flag
  ([repository commit `2818426`](https://github.com/mich-murphy/nix-config/commit/28184268fbb0510bca180aab7246e6f7a69746ee)).
- On 29 May 2026, Homebrew changed `brew bundle install --cleanup` so it would
  no longer remove packages unattended without an explicit force or ask mode.
  That change introduced `--force-cleanup` for noninteractive post-install
  cleanup. It kept `--zap` as the switch selecting cask zap instead of ordinary
  uninstall
  ([Homebrew commit `e0d818b`](https://github.com/Homebrew/brew/commit/e0d818bbbd6c7a28e336f2f89992ad696136d5d9)).
- On 5 June 2026, this repository added
  `extraFlags = ["--force-cleanup"]`
  ([repository commit `a667f37`](https://github.com/mich-murphy/nix-config/commit/a667f37ef90739dacde5df3f4aee3042842ad6e4)).
  Its nix-darwin input was still revision `56c666e`, whose `cleanup = "zap"`
  implementation emitted only `--cleanup --zap`
  ([historical nix-darwin source](https://github.com/nix-darwin/nix-darwin/blob/56c666e108467d87d13508936aade6d567f2a501/modules/homebrew.nix#L184-L185)).
  The extra flag therefore supplied the new explicit permission needed for an
  unattended activation.
- On 8 June 2026, Homebrew formally marked the install-time `--cleanup` option
  as deprecated. The adjacent `--zap` option remained supported
  ([Homebrew commit `bc44e3d`](https://github.com/Homebrew/brew/commit/bc44e3d0192104840b4543bf781d7db95814e95d)).
- On 17 June 2026, nix-darwin replaced its generated `--cleanup` flags with
  `--force-cleanup`; its `"zap"` mode now emits
  `--zap --force-cleanup`
  ([nix-darwin commit `bb9c29c`](https://github.com/nix-darwin/nix-darwin/commit/bb9c29c19327336fa499fe77bd7ba6d00ccec484)).
- This repository first moved to a nix-darwin revision containing that fix on
  14 July 2026
  ([repository commit `15f713e`](https://github.com/mich-murphy/nix-config/commit/15f713e55c4b77309009bec61beba66bf232adb7)).
  From that point, the explicit `extraFlags` entry duplicated the flag
  generated by nix-darwin.

## Current semantics

The official Homebrew manual currently defines `--force-cleanup` as cleanup
after installation without prompting, while `--zap` chooses `zap` rather than
`uninstall` for casks
([Homebrew manual](https://docs.brew.sh/Manpage#bundle-subcommand)).

The currently locked nix-darwin revision emits
`--zap --force-cleanup` automatically for `cleanup = "zap"`
([locked nix-darwin source](https://github.com/nix-darwin/nix-darwin/blob/57a3171f94705599a2499248ca5758d5eb47c0e0/modules/homebrew.nix#L196-L197)).
Adding `extraFlags = ["--force-cleanup"]` would only repeat the same argument.

The precise correction to the remembered statement is:

> We added `--force-cleanup` when Homebrew made install-time cleanup require
> explicit confirmation; Homebrew later deprecated `--cleanup`. `zap` itself
> was not deprecated. Newer nix-darwin handles `--force-cleanup` automatically,
> so our extra flag became redundant.
